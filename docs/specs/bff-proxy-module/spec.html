BFF upstream-proxy module

Visual companion to spec.md. Extract the proxy policy out of the Next.js route handler into a deep module on standard Request/Response.

The problem: deep code, unusable seam

180 LOC of security policy (header hygiene, cookie host-binding, redirect rewriting, path re-encoding) is fused to Next.js plumbing. The interface is 7 method exports bound to NextRequest. Zero tests in apps/web, and this is the riskiest untested code.

Before

one module: policy + Next plumbing fused. Test surface = run a Next server.

After

thin adapter + deep module. Tests drive plain Request objects.

Env reads stay inside src/app/api/ (check-bff.sh boundary). Config is passed in, so the module never touches process.env and tests need no env manipulation.

The test seam

graph LR T["tests: new Request()"] --> M["handleUpstream"] M --> SF["stub fetch
(assert args, return canned Response)"] M --> OUT["assert Response:
status, headers, set-cookie"]
  • client x-forwarded-* never reaches upstream
  • cookie Domain stripped; set-cookie re-emitted host-bound
  • upstream location rewritten to public origin
  • %2F path segments cannot reshape upstream path
  • upstream throw -> 502; bad segments -> 400
  • no-body statuses drop the body

Why this first

Largest source file, only security-critical untested code, behavior-preserving refactor. After it, the riskiest code in the repo is testable through a plain Request/Response seam.
