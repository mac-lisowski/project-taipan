Deepen the users slice

Visual companion to spec.md. Move registration rules out of the HTTP router into a users module over an injected Session.

The problem: rules live in the adapter

Before

router holds uniqueness + hashing + construction; repository is a pass-through to Session.

After

router maps statuses; module owns rules behind a small interface.

Module shape

graph LR subgraph "router - thin adapter" REQ["POST /users"] --> MAP["map errors
EmailTaken -> 409
NotFound -> 404"] end subgraph "users module - deep" MAP --> REG["register(email, password)
get / list / remove"] REG --> RULES["uniqueness check
hash_password
typed errors"] end RULES --> REPO["UserRepository (unchanged)"] REPO --> DB[("Session - injected")]

No FastAPI imports inside the module. Domain errors, not HTTPException. Callers map to their own error mode.

The test seam

graph LR T["tests: real test-DB session"] --> M["users.register / get / remove"] M --> A["assert: hashed pw, EmailTaken,
NotFound, rows persisted"] H["HTTP tests (unchanged)"] --> MAP2["pin error -> status mapping"]
  • register returns User with hashed (not raw) password
  • duplicate email raises EmailTaken
  • get on missing id raises NotFound
  • existing HTTP tests pass unchanged

Why it matters

Locality ahead of growth: auth and sessions land in this slice next. They should land on a deep module with rules in one place, not on routers that accumulate domain logic.
