Change flow

sequenceDiagram actor U as user participant P as account page participant D as change module U->>P: current + new x2 P->>D: change request D->>D: verify current D->>D: check new rules D->>D: store new hash D-->>P: ok or typed error P-->>U: success note or fix hint

Test seam note

Rule tests hit the change module with a real test session. HTTP tests pin the error map only. UI tests pin form states and the success note. No plain passwords in logs.

Out of scope

Reset by mail, admin set, two factor, long history. Tokens stay single use, hashed at rest, short life.
