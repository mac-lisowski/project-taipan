Platform KMS key provisioning

One idempotent command makes or finds the platform key. The admin token never enters the app runtime. Spec: docs/specs/planned/platform-key-provisioning/spec.md.

Setup flow

flowchart LR O["operator: INFISICAL_ADMIN_TOKEN"] --> S["scripts/provision_kms.py"] S --> F["find or create project + key"] F --> I["Infisical KMS"] I --> K["key id on stdout"] K --> E["API_INFISICAL_KMS_KEY_ID"] S -. optional --verify .-> V["runtime token roundtrip"] V --> I

Re-runs change nothing. Verify catches a missing identity grant at setup, not at boot.

Identity split

Admin token: provisioning only, script only

Runtime token: encrypt + decrypt only, app only

The two-identity rule in packages/kms stays intact. App code does not move.

Test seam

  • Find ops: live tests against self-hosted Infisical.
  • Create-or-get: pure function over finders, unit tests with fakes.
  • Verify: thin Cipher call, one fake test pins the failure shape.

Out of scope

Per-tenant keys (dropped), rotation automation, identity grants, CI provisioning, Spec B schema work.
