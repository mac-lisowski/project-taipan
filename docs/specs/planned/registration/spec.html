Registration

Email only sign up. Mail a link. Set a password. Auto login. Land on /dashboard. Spec: docs/specs/planned/registration/spec.md.

Request flow

flowchart TD A["/register: email only"] --> B["POST request: email"] B --> C["email seam: send link"] C --> D["/activate?token=: set password"] D --> E["POST activate: token + password"] E --> F["auto login: session cookie"] F --> G["/dashboard"] L["POST login"] --> G

Module seam

flowchart LR R["registration module"] --> M["email delivery seam"] M --> V["Resend adapter"] R --> T["token store: hash + expiry + used"] R --> S["sessions table pattern"] S --> G2["/dashboard"]

One mail seam for all mail. Tokens are single use, hashed at rest, short lived. Sessions reuse the current table pattern.

Test seam

  • API over HTTP with real test DB. Fake mail seam. Assert one send, link holds token.
  • Pins: reuse fails, bad link fails, old link fails, hash at rest, no login before set.
  • Web: pure choice functions, stubbed fetch. Success lands on /dashboard.

Out of scope

Password reset, invites, social login, rate limits, extra roles, rotation.
