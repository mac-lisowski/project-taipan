Email at rest encryption

users.email becomes ciphertext. A keyed hash column owns lookup and uniqueness. Spec: docs/specs/planned/email-at-rest/spec.md.

Write and lookup paths

flowchart LR A["email input"] --> N["normalize: trim + lowercase"] N --> H["HMAC-SHA256"] --> IH["email_hash, unique index"] N --> E["EncryptedString envelope"] --> C["users.email"] Q["login or reset"] --> H P["reset, activation, admin reads"] --> S["resolve tenant via user_tenants"] --> D["re-scope, decrypt"] --> C

Lookups hash and match on the index. Plaintext only ever leaves under the user's tenant scope.

Key material

Before: plaintext email, env holds only the wrapping key id

After: envelope + keyed hash, HMAC key wrapped like a DEK

One platform KMS key wraps everything. The HMAC key never lives in env.

Test seam

  • Live: register, login at any case, reset, admin list, roundtrip decrypt.
  • Unit with fakes: normalization, hash determinism, duplicate hash rejected, scoped decrypt.
  • Migrations: information_schema checks on scratch databases, not create_all.

Out of scope

Delivery tables stay plaintext-keyed, no substring search, no per-tenant keys, no handshake change, other columns wait for a later spec.
