First-run setup wizard

Zero users means setup, not login. The first user becomes admin; open registration closes behind them. Spec: docs/specs/planned/setup-wizard/spec.md.

The single-shot seam

flowchart LR H["POST /api/setup"] --> L["pg_advisory_xact_lock"] L --> C{"users empty?"} C -->|yes| W["tenant + user +

The lock serializes bootstrap; the recheck inside it makes the second caller lose. Enforcement lives in the database, not in a count check.

Authorization switch

  • user_roles extension table: Pattern A, no users columns. Migration backfills admin to the earliest user.
  • require_admin dependency: 401 no session, 403 no role. Gates the users router; profiles stay open.
  • Lock and recheck live in the users module; the router maps outcome to 201/409 (thin-router convention).

Test seam

  • Api: HTTP through the test client against real app_test; setup once per test via fixture.
  • Pins: 201+cookie+role on first setup, 409 on second, 403 for non-admin session, 401 without one.
  • Migration backfill tested on the scratch-DB alembic harness (upgrade, seed, upgrade, assert earliest user is admin).
  • Web vitest: pure decision functions only (probe to form, redirect predicate), stubbed fetch - no React rendering.

Out of scope

Self-service authz, invites, password reset, admin UI, rate limiting, org tenants, extra roles.
