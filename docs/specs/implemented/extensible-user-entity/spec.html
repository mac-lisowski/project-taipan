Extensible User Entity (Pattern A)

Visual companion to spec.md. Keep core User minimal and extend via separate 1:1 or 1:N extension tables.

Architecture: Extension Tables vs Bloated Core

Anti-Pattern (Bloated Core)

Table: users

  • - id (PK)
  • - email
  • - hashed_password
  • - display_name (pollutes core)
  • - avatar_url (pollutes core)
  • - billing_address (pollutes core)

High coupling and frequent schema merge conflicts.

Pattern A: Extension Tables (Selected)

users (Core Auth)

id, email, hashed_password, is_active

user_profiles (Extension Table)

id, user_id (FK), display_name, bio, avatar_url

Clean isolation. Downstream additions never touch core tables.
