Tenant-Scoped Roles and the System Owner Role

Status: planned. This page is the map. Read spec.md for the prose.

1. Target shape

One service owns grants. Two tables hold the two kinds. The guard checks tenant roles. System roles stay tenant-less.

2. Before and after

One global grant table becomes two scoped tables. Scope is the depth that gets added.

Before

user_roles: user_id + role, global

One table. No tenant column. The guard skips it. Admin means admin everywhere.

After

user_tenant_roles: user_id + tenant_id + role, guard-checked
user_system_roles: user_id + role, tenant-less

Tenant power and platform power get separate homes, checks, and unique rules.

3. Test seam

Two seams, both existing. No new seam.

HTTP seam

Crosses: setup, login, /me, /users via the app test client.

Asserts: setup grants admin + member in the created tenant plus system_owner. /me returns roles and system_roles. Members get 403 on /users, admins get 200.

Migration seam

Crosses: real alembic upgrades on a scratch database.

Asserts: exact DDL of both tables, every old grant backfilled into the linked tenant, earliest user gets system_owner, final revision drops the old table.

Plus one guard test: a tenant-role write outside scope fails, inside scope passes.

4. Out of scope

Shared tenants, tenant switching, more system users, role admin UI, new role values, session changes. The one-to-one user-tenant link stays.
