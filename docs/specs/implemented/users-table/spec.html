Users Table

Owner only page. Registered users in a table. Search, status filter, page size, pager. Spec: docs/specs/planned/users-table/spec.md.

Page flow

flowchart TD O["system owner"] --> N["nav: system section"] --> P["/users"] P --> L["lib: load users via BFF"] L --> F["pure: search + filter + page"] F --> T["table: email, badge, date"] V["non owner"] --> R["redirect /dashboard"] A["no session"] --> L2["redirect login"]

Module seam

flowchart LR P["users page"] --> LIB["users lib: states + pure helpers"] LIB -- "GET /api/users via BFF" --> U["existing users endpoint"] P --> UI["ui barrel: table, select, badge, input, button"]

Web only. The API gains no code. The endpoint result is the only source of list state.

Test seam

  • Web lib tests with stubbed fetch. Loader calls the BFF users path, maps body and failures.
  • Pin pure helpers: case insensitive email search, status filter, page slicing and bounds.
  • No render tests. Known repo gap, same as the auth forms.
  • API gains no tests because it gains no code.

Out of scope

Server paging and query params, row actions, role and name columns, tenant scoping of the endpoint, sorting, CSV export.
