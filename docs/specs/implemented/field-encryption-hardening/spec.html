Field-encryption hardening

Fail-fast on KMS outage, one home for api test helpers, public accessors for wiring tests. Spec: docs/specs/field-encryption-hardening/spec.md.

Breaker state machine (on the Cipher port)

stateDiagram-v2 [*] --> closed closed --> closed : KmsError under threshold closed --> open : threshold consecutive KmsError open --> open : any call -> kms_unavailable, no wrapped call open --> half_open : cooldown elapsed, one probe admitted half_open --> closed : probe succeeds, count resets half_open --> open : probe fails, cooldown restarts

Only KmsError trips it. Decrypt authentication failures never reach the breaker, so data problems stay data problems.

Test seam

  • Breaker unit tests cross the Cipher port with a stub and a fake clock; they assert outcome and category per transition.
  • Wiring tests cross the new accessors (cipher/store/cache, local/remote) and assert types, no privates.
  • Helper tests import from the shared api support module; the crypto package keeps its own fakes on purpose.

Out of scope

Negative caching, DekStore and DekCache breaking, cross-process or per-tenant breakers, AESGCM instance caching, changes to never-cache-failed-unwrap or single-flight.
