Split InfisicalKms along the two-identity seam

Visual companion to spec.md. Two adapters over a shared transport, so the type structure encodes the documented identity model.

The problem: the identity rule is prose-only

Docs describe two tokens with different powers. One class implements both ports, so a runtime-token object still offers rotate and fails only at runtime (HTTP 4xx).

Rotation becomes unnameable for a runtime token, not merely unauthorized. The provisioner keeps Cipher powers because the admin identity can encrypt too.

What changes vs what doesn't

Changes

  • InfisicalKms removed, two adapters exported
  • fixture uses provisioner; crypto tests pick per case
  • new structural test: cipher has no provisioning methods

Unchanged

  • HTTP contract, endpoints, envelopes (verified v0.165.16)
  • KmsError semantics
  • skip-when-unreachable test convention
  • the four live tests' assertions

Honest counterweight

Today the only consumer is the test fixture, which legitimately wants both powers. The split pays off when runtime code lands; doing it now keeps that future diff small.
