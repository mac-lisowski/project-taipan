Email delivery package

Visual companion to spec.md. One seam for all sends. Resend in prod. Fake in dev.

Module seam

graph LR subgraph "app code" A["auth flows"] --> S["sender.send: template + data + to"] end S --> T["templates: one per email"] T --> G["suppression check"] G -->|clean| R["Resend adapter: prod"] G -->|local or test| F["fake adapter: in memory"] G -->|suppressed| X["short circuit: suppressed"] R --> L["log outcome"] F --> L

App code sees the sender only. Adapter choice happens once at startup from config.

Contracts kept

  • All sends cross the one package seam.
  • Tokens stay single use, hashed, short lived.
  • Login and activation land on dashboard.
  • Sessions reuse the current table pattern.

Bounce stance

  • Log each outcome with template and cause.
  • Hard bounce marks address do not send.
  • Soft bounce retries a small bound, then stops.
  • No inbound mail in this spec.

Test seam

graph LR T1["tests: fake adapter"] --> T2["send activation or login"] T2 --> T3["read captured link"] T3 --> T4["complete flow: land on dashboard"]
  • One render case per template.
  • Missing data fails before send.
  • Suppressed address never calls vendor.
  • No test hits real Resend.

Why it matters

One seam keeps keys, copy, and failure modes in one place. Dev stays safe. Tests stay fast.
