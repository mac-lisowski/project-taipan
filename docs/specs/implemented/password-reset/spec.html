Password reset

Visual companion to spec.md. Forgot link plus token reset over one mail seam.

Module and seam map

graph LR subgraph "thin adapters" R1["POST forgot - email in, neutral reply"] R2["POST reset - token plus new password"] end subgraph "password-reset module - deep" R1 --> REQ["request: silent lookup, mint token, store hash"] R2 --> RST["reset: check token, set hash, burn token, revoke all"] RST --> SES[("sessions table pattern")] end REQ --> MAIL["email-delivery seam - Resend adapter"] MAIL --> LINK["link mail to known email only"] RST --> LOGIN["new login session - land on /dashboard"]

Tokens are single use, hashed at rest, short expiry. Unknown emails get the same reply and no mail. Routers map errors and cookies only.

The test seam

graph LR T["tests: real session plus stub mailer"] --> M["request / reset acts"] M --> A["assert: hash not raw, one mail, burn, revoke"] H["HTTP tests"] --> MAP["pin neutral reply, error map, cookie, /dashboard"]
  • known email stores a hash and queues one link
  • unknown email sends nothing, same reply
  • reuse or past expiry fails
  • reset kills all old sessions, then logs in

Why it matters

One mail seam stops sender drift. Hash plus expiry plus revoke keeps a leaked link weak.
